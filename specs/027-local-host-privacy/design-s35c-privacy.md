# S3.5c 隐私与流式输出

**依赖** 显式 Key 策略以及 Chat 与 Responses 的统一出站处理边界。

- 默认 `off`。管理员按 Key 选择 `standard` 或 `strict`；管理页提供本地、无落盘的预览，只记录规则版本和命中分类计数。
- 在序列化所有出站尝试之前，按协议允许的字段处理 JSON 字符串值；保留字段名、工具 schema、结构和非文本输入。对当前不支持的字段与协议明确标注覆盖范围；`strict` 对无法保护的请求返回稳定错误。
- 占位符使用请求级随机命名空间，对原文碰撞做校验，映射仅在单请求及其 SSE 生命周期内存在。fallback 继续使用同一份脱敏输入；规则或转换失败时有保护的请求在出站前终止。
- SSE 按输出项和工具调用标识隔离缓冲区，分块状态有上限。仅在获准的展示文本中恢复精确匹配，工具参数保持脱敏或按策略拒绝。未知或变形标记保持脱敏；`strict` 在识别到应拦截的异常时停止输出并提供合规的终止语义。
- 启用本地脱敏时绕过语义缓存。日志、trace、审计与备份只保存必要元数据。图片内容和跨请求恢复不属于首版覆盖范围。

**验收** 用本地 fixture 检查上游未收到原值，覆盖分片、多个输出项、断流、fallback、伪造标记、规则失败和工具参数。独立记录 Chat 和现有 Responses 文本子集的覆盖范围。
