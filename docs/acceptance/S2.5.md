# S2.5 Responses 最小子集验收

**日期：** 2026-11-16
**分支：** `feat/standalone-control-plane`
**基线提交：** `6f9ab49`
**验收级别：** Windows 本机自动测试；使用 `net/http/httptest` 的进程内 loopback 服务和 `mockopenai` 上游。不是完整 Responses、Codex、真实 Provider 或公网验收。

## 已实现能力

- 数据面注册 `POST /v1/responses`，使用本机 Key 鉴权，并经过 Key 准入与模型解析路径。
- 接受字符串 `input`，也接受由 `user`、`assistant`、`system` 文本消息组成的数组。
- 非流式请求返回 `object:"response"`、`status:"completed"` 和上游文本输出。
- 流式请求返回 SSE；测试实际断言 `response.output_text.delta` 和 `response.completed`，代码还会输出 `response.created` 与 `response.output_text.done`。
- 解析层允许 `instructions`、`max_output_tokens`、`temperature`、`metadata` 等字段；本次测试只直接覆盖 `model`、`input` 和 `stream`。
- 对 `tools`、`tool_choice`、`previous_response_id`、`store`、`reasoning`、`text`、`include`、`background`、`truncation` 明确返回 422，不使用静默忽略。

## 未实现或未验收

- function/tool calling 未实现：只要请求对象出现 `tools` 字段（包括空数组）就返回 422 `unsupported_response_field:tools`。
- 上述未支持字段中，本组测试只直接断言了 `tools`；其余字段由实现检查确认，未逐项构造请求验证。
- 因此没有完成 Codex 只读工具往返，也不能声称 Codex 兼容。
- `previous_response_id`、服务端会话、存储响应、后台执行和完整 Responses 事件状态机均未实现。
- 没有覆盖内置工具、多模态输入、完整输出 item 形状、取消/断流、失败事件或异常上游流。
- `instructions`、`max_output_tokens`、`temperature`、`metadata` 只有解析路径，未在本组测试中逐项验证语义；`metadata` 不会据此视为已实现完整响应契约。
- 没有执行真实 Provider 联调；只使用 `mockopenai`。
- 没有执行浏览器 UI、局域网/TLS、公网或 Codex CLI 验收。

## 重启与错误路径证据

- 本组测试没有执行重启。Responses 路径没有实现服务端会话或响应持久化，因此不能把重启后的会话延续写成已验收。
- 非流式请求返回状态 `completed`；流式请求包含文本 delta 和 `completed` 事件。
- 携带 `"tools":[]` 的请求返回 422，错误包含 `unsupported_response_field:tools`，证明未支持字段不会被静默忽略。
- 代码在上游返回工具调用块时会以 `unsupported_tool_output` 失败，但本组测试没有构造该上游输出。
