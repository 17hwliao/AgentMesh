# S2 路由回退、用量与限额验收

**日期：** 2026-11-16
**分支：** `feat/standalone-control-plane`
**基线提交：** `6f9ab49`
**验收级别：** Windows 本机自动测试；使用 `net/http/httptest` 的进程内 loopback 服务和 `mockopenai` 上游。不是真实 Provider、并发压测或公网验收。

## 已实现能力

- 管理 API 可创建启用的路由组，并按 `priority` 排列成员；模型公共 ID 与路由组名都可作为请求模型。
- 首跳上游返回 401、429 或 500 时，测试证明可在首包前回退到下一优先级成员，最终返回完整 SSE 和 `[DONE]`。
- 429 会记录 `rate_limited` 冷却；下一轮请求跳过仍在冷却的成员，不再重试该成员。
- `/admin/usage` 可返回聚合用量和当前冷却行；测试观察到两轮成功请求归属到 secondary 的 `requests:2`，以及 `reason:rate_limited`。
- 可创建带 RPM 的 `app_key`；`rpm=1` 时第一次请求成功，第二次返回 429 `quota_exhausted`。
- 模型白名单会阻止未授权模型：只允许 `secondary/mock-small` 的 Key 请求 `primary/mock-small` 时返回 403。
- `auth_type=none` 的 OpenAI 兼容上游可完成 Chat 请求，不要求上游 Bearer Key。
- 重启后启用目录、Key 哈希、路由组和持久化用量仍可使用；同一 `local` Key 可立即请求 `auto` 路由。

## 未实现或未验收

- 本组测试只证明顺序请求下的 RPM 限制，没有证明并发硬限额不会穿透。准入检查与用量记录不是原子的 `Reserve → Settle / Release`；并发预留和结算仍未验收。
- `daily_requests`、`daily_tokens` 和过期时间等字段虽有目录/管理面表示，但本组验收只直接证明 RPM 与模型白名单。
- 测试没有直接断言“首包后绝不回退”；只覆盖了收到上游错误状态、尚未产生正常首包前的回退。
- 没有验证按权重比例分配流量。当前测试只证明按优先级回退，权重不构成已验收的加权调度能力。
- standalone/catalog 当前没有 `context_window` 字段或过滤路径；上下文窗口筛选未实现。本阶段也未形成完整的能力过滤验收。
- 冷却是进程内状态并持久化到 SQLite；测试证明重启后路由和用量仍可用，但没有单独断言重启后首跳一定因冷却被跳过。
- 用量行按完整请求记录最终成功使用的 Provider；首跳失败的尝试由 mock 调用计数和冷却行证明，不是逐尝试 usage 行。
- 没有执行真实 Provider 联调、浏览器 UI、局域网/TLS、公网、可信代理、MySQL/Redis 或多副本验收。
- S1b 的完整设备 Key 验收不在本文范围；S2 测试只使用其创建 Key 的最小管理路径。S1b 验收记录待补。

## 重启与错误路径证据

- 429 回退场景中，primary 被调用 1 次、secondary 被调用 1 次，客户端得到 200 和完整 SSE。
- 冷却后的下一轮请求成功，primary 的调用计数不再增加，证明冷却中的成员会被跳过。
- 401、429、500 三个子测试均从 primary 回退到 secondary，并返回 `hello from mock`。
- `rpm=1` 的 Key 第二次顺序请求返回 429 `quota_exhausted`；白名单不匹配返回 403。
- 测试关闭并重新打开同一数据目录后，`auto` 路由仍返回成功，`/admin/usage` 仍包含持久化 `rows`。

## 环境限制

- WSL bash 不可用；所有实际执行的命令均在 Windows PowerShell 中完成。
- `GOMEMLIMIT` 设为 `3GiB`。
- 自动测试使用进程内 loopback 和 mock 上游，不能外推到真实 Provider 的 401/429/5xx 行为、真实 token 计费或并发生产流量。
- `git diff --check` 不检查未跟踪文件；三份新增验收文档另用 PowerShell 检查尾随空白，结果均为 0。
- 本阶段只运行了指定测试、`go vet ./internal/standalone` 和 `git diff --check`；未运行全仓测试、race、并发限额压测或真实进程验收。
