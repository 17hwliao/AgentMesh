# S3 双实例 Remote AgentMesh 本地模拟验收

**日期：** 2026-11-16
**分支：** `feat/standalone-control-plane`
**基线提交：** `6f9ab49`
**验收级别：** Windows 本机自动测试；使用两个进程内 `standalone.App` 实例、`net/http/httptest` 的 loopback listener 和 `mockopenai` 上游。不是真实局域网、真实第二台设备、真实进程部署或公网验收。

## 已实现能力

- 测试启动两个独立 App：实例 A 负责上游 Provider、设备 Key 和 TLS 数据面；实例 B 使用独立数据目录、管理面和本机 Key。
- 实例 B 可以通过 `kind=agentmesh`、Bearer 认证和 A 的 `/v1` 地址创建 Remote Provider，并执行模型发现、列表和启用。
- A 的数据面由 `httptest.NewTLSServer` 包装为自签 TLS。B 未设置 `tls_insecure` 时，发现请求返回 502；测试期间 A 打印 `tls: bad certificate`，证明默认 TLS 校验确实拒绝了自签证书。
- Provider 的 `tls_insecure=true` 可以保存并从 catalog 读回为 true；Provider HTTP 客户端据此只为该 Provider 设置 `InsecureSkipVerify`，不从 URL scheme 推断不安全连接。
- 两个远程 Provider 分别使用 device A 和 device B 的独立 Key。B 的本机 Key 请求 `office` 和 `branch` 两个 Remote 模型均返回成功。
- 撤销 device A 后，依赖 device A 的 `office` 模型请求失败；依赖 device B 的 `branch` 模型仍成功。
- A 的管理列表显示 device A 已禁用、device B 仍启用，证明设备 Key 的撤销隔离。

## 明确未实现或未验证

- 这不是局域网部署：两个 App、TLS listener 和测试客户端都在同一台 Windows 机器、同一测试进程内，通过 loopback 通信。
- 没有验证 `0.0.0.0`、RFC1918、真实第二台设备、mDNS、二维码或防火墙配置；当前 standalone 配置仍只接受 loopback 地址。
- 没有真实 `cmd/api --standalone` 进程启动，也没有独立 TLS listener 或证书管理。TLS 仅由 `httptest.NewTLSServer` 在测试中包装处理器。
- 没有 mTLS、CA 信任链配置、证书轮换或 `tls_insecure` 重启持久化回归；本轮只验证创建后 catalog 读回和即时调用。
- 没有浏览器状态页、设备调用量页面或最近错误码页面验收。
- 撤销后的远程失败只断言为“非 200”，没有单独断言具体错误状态码或上游错误码。
- 没有 MySQL/Redis、多副本、可信代理、公网、真实 Provider 或高可用验收。

## 错误路径与回滚证据

- 自签证书默认不可信：未设置 `tls_insecure` 的 Remote Provider 发现返回 502，A 侧记录 TLS handshake 证书错误。
- 显式设置 `tls_insecure=true` 后，同一 loopback TLS 上游可以完成发现和 Chat；这是测试内的显式不安全开关，不应外推为公网安全方案。
- 撤销 device A 后，`office` 请求失败而 `branch` 请求成功，证明一个设备 Key 的撤销不会改变另一个 Key 的准入。
- 没有执行失败 Provider 配置的事务回滚或重启回滚测试；操作回滚应恢复一致的 `catalog.db` 和 `master.key`，或删除/禁用 Remote Provider，本轮未演练。

## 环境限制

- 所有实际执行的命令均在 Windows PowerShell 7.6.9 中完成。
- Go 版本为 `go1.26.11 windows/amd64`，`GOMEMLIMIT` 设为 `3GiB`。
- 测试只使用 loopback 和 `mockopenai`，不能证明真实局域网发现、跨设备网络、证书部署或生产负载。
- 当前实现和测试没有把 S3 写成已上真机；文档中的“双实例”均指同一测试进程内的两个 App 实例。
